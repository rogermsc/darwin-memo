\paragraph{Historical integration boundary.}
The compatibility command reads ticket references from pull-request metadata
and can compare changing JUnit suites or raw pass counts. Those inputs require
review: a ticket reference does not establish task ownership, and a pass-count
change need not represent an improvement on the same evaluation. The base-store
check rejects tickets already pending in the supplied base; without that base,
ticket provenance remains unverified. This check is narrower than authentication.
The fixed-evaluation profile described above adds task and run binding and
separately reports evaluation-file changes. An actor with direct store or runner
write access remains outside its accidental-misattribution protection.
